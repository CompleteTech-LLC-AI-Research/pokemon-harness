# #389 / #390 / #394 / #426 — non-enterable `with` headers

Base `e968333`, worktree `/workspace/poke-harness/.scratch/fixC`, branch
`fix/389-390-394-426-nonenterable`.

## Diagnosis

All four are the same root cause: a value that cannot implement the context
manager protocol is bound in the `with` header. Entering it raises before the
body, so the assert is unreachable — and the analyzer reported **enforced**,
certifying a disarmed contract as load-bearing. That is the damaging
direction.

| Issue | Shape | Runtime | Analyzer before |
|---|---|---|---|
| #389 | `from os import path as cs` | `TypeError` | `True` |
| #390 | `cs = lambda: None` | `TypeError` | `True` |
| #394 | body `import json as fake` shadows module-level `fake` | `AttributeError` | `True` |
| #426 | `with (*cs,):` enters a **tuple** | `TypeError` | `True` |

Each failed a *different* gate, which is why no single existing rule caught
them:

* **#389** — `_carrier_runtime_kinds` declines every `ImportFrom` on purpose.
  The decline is correct in general: `from contextlib import nullcontext as cs`
  binds something genuinely enterable. The question is not "is this an
  `ImportFrom`" but "what does *this* attribute resolve to".
* **#390** — `ast.Lambda` was not in the readable-literal set, so a `cs = lambda`
  store was declined as "a call is a call".
* **#394** — the header expression is a `Call`, so the name-based
  `_entered_name_is_dead` never saw it, and the shadowing import was invisible.
* **#426** — the header is a `Tuple`, which the `ast.Name` gate skipped.

## Fixes

| File | Change |
|---|---|
| `_sentinel_support_part1.py` | `_carrier_runtime_kinds` consults `_from_import_kind` for `ImportFrom as` |
| `_sentinel_support_part6.py` | `_literal_runtime_type` reads `Lambda` → `function`; `_entry_is_dead` settles an all-starred tuple header; new `_from_import_kind`, `_module_lacks_attribute`, `_header_expression_raises`, `_imported_module_name` |
| `_sentinel_support_part10.py` | calls `_header_expression_raises` from the `with` ancestor arm |
| `_sentinel_support_base.py` | `import sys`, `import types` |

`_from_import_kind` and `_module_lacks_attribute` resolve against the **real
interpreter** and return a runtime type only for a value that cannot implement
the protocol; an enterable or unresolvable attribute returns `None`, so a live
header keeps its assert. That is what keeps the existing control green.

## One existing test rewritten, with its premise superseded

`test_an_import_from_as_is_declined_rather_than_read_as_a_module` asserted
`[True]` for all three `ImportFrom` rows, on the stated premise that the value
"is not readable off the syntax". That premise is what #389 removes, and two
of the three rows are genuinely dead — the test was pinning three dead
contracts as live. It is now
`test_an_import_from_as_is_resolved_rather_than_declined` and asserts `[False]`,
with the docstring and the `UNDECIDABLE_IMPORT_FROM_SHAPES` comment rewritten to
say so.

The control it depended on,
`test_an_import_from_as_can_bind_a_real_context_manager`, **still passes
unmodified** and is what makes the resolution per-attribute rather than
per-spelling. It is the row that breaks under a rule answering "module" for
the whole shape.

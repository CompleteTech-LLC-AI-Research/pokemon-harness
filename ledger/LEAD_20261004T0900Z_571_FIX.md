# PR #571: repair the #566 directive-gate regression

## What changed

`53b6a97a` (#566) carried a blocking defect the lead proved: the
`maybe_directive()` prefix gate skipped any comment not literally starting with
one of ten strings, while Ruff's grammar allows any run of whitespace between the
comment marker and the keyword. `#  ruff: noqa` silenced an entire file and the
row still passed. `16d102e` had *removed* coverage the branch already had — the
pre-`16d102e` row rejects that same spelling.

Repaired on branch `fix/106-directive-normalization`, worktree
`/home/agent/wt566fix`, commit `23333c8`. Opened as PR **#571**, which is a
candidate replacement for #566's head. PR #566 remains open and rejected.

The fix replaces the prefix tuple with a normalized match:

    directive_keyword = re.compile(r"\A#+\s*(?:ruff|flake8|fmt|yapf|noqa)\b", re.IGNORECASE)

`silences()` still decides anything that reaches it, so a match that turns out
to be inert costs one subprocess and changes no verdict.

## Two measurement errors I made and corrected

Worth recording, because both produced a confident wrong answer:

1. **Shell tab escaping.** `printf '#\truff: noqa\n'` emitted a *literal*
   backslash-t under `/bin/bash`, so the "planted" directive was not a tab and
   not a directive at all. This made me briefly conclude Ruff rejects
   tab-spaced directives. Building mutants in Python removed the doubt: Ruff
   silences on tab spacing too, and the row must catch it.
2. **Inverted exit-code logic.** I wrote `if ruff check ...; then reported; else
   silenced; fi`. `ruff check` exits 0 both when it finds nothing and when
   everything is suppressed, so this reported the exact opposite of the truth.
   Judging suppression now means reading Ruff's *output* against a control file.

Also: a first venv had no `ruff` installed, and the row correctly failed closed
rather than passing vacuously. That is the intended behavior and is worth
keeping.

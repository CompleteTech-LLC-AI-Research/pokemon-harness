# #253 — synthesis: what is actually left, after two independent measurements

Master at time of writing: `8ae604c3`

Two measurements from different actors on different trees converge on a single conclusion about
#253, and the remaining work is now small and specific.

## The two measurements

### A. The read-only `/dev/shm` penalty is +26 unit failures

`ledger/LEAD_20261004T1755Z_253_SHM_READONLY_DELTA.md` — identical tree and pytest surface, mount as
the only variable:

| `/dev/shm` | unit result | duration |
|---|---|---|
| writable (nested-namespace wrapper) | `total=8327 passed=8318 failed=6 skipped=3` | 1657.0 s |
| read-only (host default) | `total=8327 passed=8292 failed=32 skipped=3` | 1926.96 s |

27 of the 32 read-only failures do not appear in the writable run at all, and they are all POSIX
shared-memory / spawn-bridge surfaces (`test_probe_owner_phases`, `test_probe_timed_rom_pair_*`,
`test_probe_timed_trade_pair_*`).

### B. The documented unit tier is truncated, so its failure count is not a verdict

`ledger/FINDING_253_UNIT_TIMEOUT_TRUNCATION_20261004.md` — the runbook's own smoke command passes no
`--timeout-seconds`, so the unit tier falls back to `DEFAULT_TIMEOUT_SECONDS["unit"] = 900.0` and is
killed at `rc=124` having run 4142 of 8327 selected nodeids.

**These two compose.** A truncated tier reports only the tests that happened to run before the
900 s ceiling, which is both a partial *set* and a load-dependent *subset*. It is not a failure
count at all — it is a snapshot of whichever tests finished first.

## What is actually left

Under a **correct** mount, the genuine residual is **6 unit failures, all in one family**: the
`TimedOwnerError` deadline failures in the timed-MCP-owner surface. Not eleven families, not 201,
not 32.

The unit tier also needs ~1657 s to complete, which is what makes the 900 s default truncating.
Raising `DEFAULT_TIMEOUT_SECONDS["unit"]` to comfortably exceed that (and documenting it in
`docs/PRODUCTION_RUNBOOK.md` §3b-0, as #577/#578/#579 already did for the wrapper) is the fix that
unblocks reading the gate at all.

## What each open sub-thread now needs

1. **Fix the harness timeout** (measurement defect — blocks every unit reading).
2. **Keep the writable-`/dev/shm` wrapper** for any unit or timing run (environment, already
   documented).
3. **The residual `TimedOwnerError` family** is contention-sensitive: I observed a whole timing
   iteration pass (`[1, 0, 1, 1, 1]`) while others failed 4–6. A fix loop must run enough
   iterations to separate "fixed" from "got lucky."

None of this changes the standing constraints: no real ROMs, no operator-declared CPU allocation,
no sustained quiet-CPU window on this host. #253 stays **open**. Release stays **PARTIAL**.

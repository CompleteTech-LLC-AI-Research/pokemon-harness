## E731 (22 findings, 9 files) — closure-capturing lambdas, semantics-neutral to convert
Representative shape (`tests/test_network_backend_shutdown.py:75`):
```python
callback = lambda core=core: core
provider = lambda core=core: {"core": id(core)}
```
These bind `core` through a default argument and are then passed as callables. Because the capture
happens in the default argument, a `def` with the same default is behaviourally identical:
```
lambda -> True | def -> True | equivalent: True
```
So unlike a bare `f = lambda x: x + 1`, these are not deferred-binding hazards — the rewrite is safe
where it is wanted. Ruff offers these as `--unsafe-fixes` precisely because it cannot prove the
capture is eager.

Decision: these are **style, not correctness**. Two defensible routes, and the choice matters:
- convert all 22 to `def`, which is a real code change across 9 files, each needing its own focused
  test run; or
- treat them as a scoped `E731` allowance alongside E402, pinned by a policy test that asserts the
  allowance does not mask anything else.

Recommendation: **convert**. Unlike E402 there is no structural reason to keep the lambda, and an
allowance that exists only to avoid a mechanical rewrite is the kind that grows.
